# ANZH Beauty — сервер

Бэкенд мини-приложения: база, сессии, записи, рефералы, оплата,
уведомления, ассистент. Построен по контракту
`2026-09-20-anzh-beauty-backend-contract.md` (редакция 2).

> 🔴 **Перед запуском на реальных людях прочитать [ОТЧЁТ-§1.md](./ОТЧЁТ-§1.md).**
> Ни один из девяти юридических вопросов не закрыт. Две красные линии:
> никаких реальных анкет здоровья и никаких реальных платежей.

## Из чего состоит

Один проект, одна база, одна кодовая база — как просит контракт §0.
Ни микросервисов, ни брокеров, ни кэша, ни ORM.

| Слой | Чем | Почему так |
|---|---|---|
| HTTP | Fastify 5 | REST, не tRPC: tRPC связывает типы клиента и сервера в одну сборку — ровно то, что мешает заменить сервер, не трогая клиент (§7.1) |
| База | PostgreSQL, драйвер `postgres` | Схема описана SQL-миграциями. ORM дал бы второй источник правды, который разойдётся со схемой на первой правке |
| Сессия | JWT HS256 на `node:crypto` | Тридцать строк против пакета с собственной историей уязвимостей. Алгоритм не читается из заголовка токена |
| Запуск | Node ≥ 22.18, TypeScript исполняется напрямую | Без шага сборки: типы снимаются рантаймом, `tsc` работает только проверкой |

Постоянный процесс, **не бессерверный**. Причина в контракте §3.5 и §9:
вебхук у бота один и переустанавливать его при каждом холодном старте
нельзя, а напоминание «за 2 часа» не работает на тарифах, где расписание
запускается раз в сутки.

## Начать работу

```bash
cd server
npm install
cp .env.example .env     # заполнить локально; в репозиторий .env не едет
npm run migrate
npm run seed             # тестовые данные, в боевую базу не едут
npm run dev
```

Проверить, что живо:

```bash
curl -s localhost:8080/api/v1/health
```

## Правила, которые нельзя нарушать

Они не про вкус — каждое чинится дороже, чем соблюдается.

1. **Миграции — только файлами и только вперёд.** Руками в консоли базы
   никогда: применённое руками невоспроизводимо, и переносить будет
   нечего. Изменение применённой миграции оформляется новым файлом —
   `migrate.ts` сверяет контрольные суммы и остановится, если файл
   поправили задним числом.
2. **Формат реферального кода не меняется.** Шесть символов
   `[A-Za-z0-9]`, выдаётся один раз, никогда не меняется. Розданные
   ссылки лежат в чужих переписках; смена формата убивает их задним
   числом, и узнают об этом только их владелицы.
3. **Ссылку собирает сервер.** Клиент её только показывает и копирует.
4. **Ни одного секрета в репозитории**, включая историю коммитов. Токен
   бота приходит по защищённому каналу и живёт только в окружении.
5. **Данные о здоровье не попадают** в логи, аналитику, текст
   уведомления и промпт модели без обезличивания (§6.4).
6. **Цены считает сервер.** Клиент присылает состав визита, а не сумму.
7. **Конфликт слота решает база**, а не проверка в коде: «проверить и
   вставить» — гонка.

## Тесты

```bash
npm test
```

91 тест, из них большая часть — **контрактные, на настоящем
PostgreSQL**, поднятом внутри процесса (PGlite по сетевому протоколу).
Ни docker, ни установленного postgres не нужно: тот же прогон работает
на чужой машине и в CI.

Так сделано потому, что тесты на моке базы проверяют мок. Самое важное
в этой схеме — уникальный индекс на подтверждённый слот, `CHECK`-
ограничения, поведение `on conflict` — мок не воспроизводит, а именно
на них всё держится. Гонка двух подтверждений на одно время проверяется
по-настоящему.

Отдельно стоит `test/openapi.test.ts`: он сверяет `openapi.yaml` со
списком поднятых сервером маршрутов. Описание расходится с кодом молча,
и узнают об этом на стыковке — поэтому сверка машинная.

## Выгрузка данных

`npm run export` кладёт в `export-out/` по файлу на таблицу плюс
`00_summary.csv` со сводкой.

⚠️ **Читать настоящим CSV-парсером, а не построчно.** Комментарий
клиентки к заявке может содержать перевод строки — по RFC 4180 он так и
лежит внутри кавычек. Экранировать его значило бы поменять данные при
выгрузке, чего §14.1 прямо запрещает. `COPY ... FROM ... CSV` в
Postgres читает такие файлы правильно.
