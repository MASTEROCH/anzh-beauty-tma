# ANZH Beauty TMA · полная спецификация

Telegram Mini App для кабинета косметолога Анжелики (Батуми).
Прод: **https://beauty-tma-prototype.vercel.app** · репозиторий `MASTEROCH/anzh-beauty-tma`, ветка `master`.

Документ описывает продукт целиком: что уже работает, как это устроено, чего нет и что для этого нужно. Составлен по коду, а не по памяти — цифры сверены с исходниками на 20.09.2026.

---

## 1. Что это за продукт

Приложение решает три задачи, которые Анжелика проговорила в голосовых записях:

1. **Запись без переписки.** Раньше клиентки писали в директ инстаграма, она вручную сверяла время и держала историю в голове. Теперь запись — это заявка в приложении, которую она принимает или переносит одной кнопкой.
2. **Память о клиенте.** Что делали, чем лечили, на что аллергия, что показал разбор кожи — всё в одном месте и видно при каждой заявке, а не восстанавливается по переписке.
3. **Диагностика до приёма.** Методология ANZH Skin Intelligence с сайта anzh.store перенесена внутрь Telegram: клиентка проходит разбор дома, Анжелика видит результат заранее и не тратит визит на расспросы.

Плюс то, что выросло по ходу: кабинет мастера с деньгами и командой, продажа разборов за Telegram Stars, генератор сторис.

## 2. Технический контур

| | |
|---|---|
| Фронтенд | React 19 + TypeScript 5.7, сборка Vite 6 |
| Состояние | Без библиотеки: синглтоны с набором подписчиков + `useState`. Один и тот же приём во всех модулях |
| Маршрутизация | Без роутера: `screen`-состояние в `App.tsx` + хеш в адресе |
| Хранение | `localStorage`, 20 ключей (перечислены в §7) |
| Бэкенд | **Отсутствует.** Ни одного сетевого вызова к своему серверу, кроме заглушки `/api/invoice` |
| Платформа | Telegram Mini App SDK (`telegram-web-app.js`), вне Telegram всё деградирует до обычной веб-страницы |
| Хостинг | Vercel, `vercel.json` с политикой кеша |
| Тесты | Playwright 1.63 на WebKit / iPhone 13 — 33 теста |
| Сборка | JS 619 КБ, CSS 158 КБ (без gzip) |

**Почему без бэкенда.** Это прототип, который должен проходиться целиком и показываться клиенту. Каждый модуль, которому нужен сервер, написан с честным швом: клиентская половина готова, серверная помечена в коде `⚠️` и перечислена в §8.

## 3. Клиентская часть

Пять вкладок: **Профиль · Услуги · Запись · Паспорт · ANZH**.

### 3.1 Онбординг

Пять шагов при первом входе: приветствие → знакомство (имя, пол) → зачем кабинет → как это работает → контакты.

- Имя подставляется из Telegram, если приложение открыто внутри него.
- **Пол спрашивается, а не угадывается.** От него зависят окончания во всём интерфейсе (`lib/gender.ts`).
- Инстаграм — главный якорь: телефонов у клиенток Анжелики почти нет.
- Пройденный онбординг запоминается (`anzh_onboarded`), заново не показывается.

### 3.2 Профиль — витрина

- Портрет, регалии, счётчики (8 лет, 1 472 процедуры, 4.9★).
- **Карусель «Как здесь всё устроено»** — сторис-формат с автопрокруткой и точками.
- **Галерея направлений** (`Gallery.tsx`): фильтры по категориям, плитка процедуры → карточка с описанием, составом и фактами → **запись прямо оттуда**. Показываются только непустые направления.
- **Отзывы** лентой + переход к полному списку, оттуда же можно написать свой.
- **Карта студии** (`StudioMap.tsx`): фрагмент OSM с меткой на реальном адресе (41.6462404, 41.6323794 — проверено по Nominatim), свой зум, кнопки «Яндекс.Карты» и «Google Maps». Карта некликабельна намеренно: собственные контролы embed не срабатывают, а видимая неработающая кнопка хуже отсутствующей.

### 3.3 Услуги — каталог

- 13 процедур в 8 направлениях: инъекции, чистки, пилинги, аппарат, уход, брови, дерматолог, **обучение**.
- Поиск, фильтр по направлению, избранное.
- Карточка процедуры: описание, что входит, противопоказания, кабинет мастера, цена в USD/GEL, длительность.
- **Обучение для коллег** — два курса: инъекционные техники $800 и авторская методика MD-Codes $1000, оба по 2 дня. Длительность показывается днями, а не минутами.
- Каталог читает **живой** список: процедура, убранная Анжеликой в архив, исчезает у клиента.

### 3.4 Запись

- Выбор даты (нерабочие дни закрыты), слота, процедуры.
- **Несколько процедур в один визит**: добавляются чипом, время и сумма складываются.
- Слот блокируется только **подтверждённой** записью — заявки друг друга не блокируют, решает Анжелика.
- Применение накопленного бонуса к сумме.
- Отправка заявки → экран подтверждения с **экспортом в календарь (.ics)** и напоминанием за 2 часа.

### 3.5 Паспорт — личный раздел клиентки

Назывался «Кабинет», переименован: это кабинет клиентки, а не врача.

- Баллы лояльности и тир (Bronze → Silver → Gold → Diamond), кэшбэк.
- Ближайшая запись, план процедур, история визитов.
- **Паспорт здоровья**: тип кожи, чувствительность, фототип, купероз, аллергии, беременность/лактация, хронические, препараты, пометки. Часть заполняется автоматически из результатов разборов.
- Бонусы и промокоды.
- Настройки: язык, валюта, уведомления, вход в кабинет мастера.

### 3.6 ANZH — разборы кожи

Методология с anzh.store целиком внутри Telegram.

- **7 разборов, 86 вопросов, 38 исходов.** Первый (Skin Profile) бесплатный, шесть платных.
- **Рекомендуемый порядок**: тип → чувствительность → качество → домашний уход → стратегия старения → морфотип. Со ступенями, галочками пройденного и подсветкой следующего шага. Порядок не случаен: каждый следующий разбор читается через предыдущий.
- **Результат** — не оценка, а разбор: тип, признаки, что делать у косметолога, процедуры Анжелики с переходом к записи.
- **Протокол домашнего ухода**: аптечная полка и профессиональная, каждая разложена на утро и вечер, шаги пронумерованы. 23 блока перенесены с сайта.
- Результаты сохраняются, уходят в паспорт кожи и видны Анжелике.

### 3.7 Оплата Telegram Stars

- Цены: разбор **670★ ≈ $12.99** (якорь 1000★), набор из шести — **2680★ ≈ $53.99**, «шесть по цене четырёх».
- Доллары показываются подписью и приглушённо: платит клиентка звёздами.
- Полный путь: **paywall → чек → вручение результата**. Чек показывает списание, срок доступа и где искать покупку.
- Только цифровое: физические товары убраны намеренно — Telegram запрещает продавать их за Stars.

### 3.8 Скидка за задания

Раньше −20% давал простой тап по шильдику. Теперь **10% за задание, до 30%**, и задания разной проверяемости:

| Задание | Как засчитывается |
|---|---|
| Отзыв | Сразу — приложение видит его само |
| Приглашение подруги | Когда она откроет приложение (реферальная ссылка) |
| Сторис с отметкой | Подтверждает Анжелика в кабинете |

Автоматически проверить сторис нельзя никак — поэтому она уходит человеку, а не засчитывается по нажатию.

### 3.9 AI-ассистент

- Шар с логотипом ANZH, пульсирует как сердце; уходит на время прокрутки, чтобы не перекрывать контент.
- Отвечает на вопросы о процедурах, ценах, противопоказаниях, часах работы; умеет открыть услугу, каталог, план или запись.
- **Ответы собираются локально** по 19 правилам сопоставления (`lib/ai.ts`) — это не языковая модель. Честный шов под настоящий бэкенд.

## 4. Кабинет мастера (админка)

Вход: **Паспорт → Настройки → Кабинет мастера → PIN**. Прямой ссылки нет намеренно — см. §6.

Демо-коды: `2024` — Анжелика (владелица), `1111` — Марина, `2222` — Нино (мастера).

### 4.1 Роли и доступ

| | Владелица | Мастер |
|---|---|---|
| Свои записи и клиенты | ✓ | ✓ |
| Чужие записи | ✓ | — |
| Касса салона | ✓ | только свой доход |
| Прайс | ✓ | — |
| Команда | ✓ | — |
| Проверка заданий | ✓ | — |

Чужая выручка закрыта намеренно: панель, где каждый видит заработок соседа, ссорит команду.

### 4.2 Вкладки

**Заявки.** Очередь заданий на проверку + новые заявки. У каждой — полоска карты клиента: был ли раньше, сколько раз, красная метка противопоказания. Действия: принять, предложить другое время, отклонить.

**Сегодня.** Расписание дня, метки противопоказаний прямо в строке, закрытие визита с суммой или отметка «не пришла».

**Клиенты.** База собирается сама из записей: визиты, суммы, неявки, приватные заметки мастера.

**Деньги.** Дашборд с двумя фильтрами — период (7/30/90 дней, год, всё время) и **сезон** (зима/весна/лето/осень), сравнение с тем же куском прошлого года, выручка по процедурам и по мастерам, аналитика неявок.

**Прайс.** Правка цен на месте, добавление своих процедур, архивирование (не удаление). Внизу — команда: добавление мастеров, свой код входа, закреплённые процедуры.

**Сторис.** Генератор макетов 1080×1920 из живых данных: свободное окно завтра, новая процедура, офер. Сохраняется PNG.

### 4.3 Карта клиента и сверка противопоказаний

Главное в кабинете. Сводит три источника — заявку, анкету здоровья, результаты разборов — и **сверяет анкету с противопоказаниями всех процедур визита**.

Словарь сопоставления: беременность, лактация, купероз, аллергии, чувствительность, препараты, хронические × слова-маркеры в тексте противопоказаний. Два уровня: **стоп** (красный, единственный красный в кабинете) и **уточнить**.

Беременность в анкете + «беременность» в противопоказаниях процедуры → красная метка **до** кнопки «Принять».

## 5. Что уже работает «на бэкенде»

Строго говоря — ничего: своего сервера нет. Но часть задач решена так, что сервер для них не нужен:

| Задача | Как решено |
|---|---|
| Личность клиента | `initDataUnsafe.user` из Telegram — ID не слетает, в отличие от ника |
| Язык | Из клиента Telegram, с ручным переключателем |
| Хранение | `localStorage`, переживает перезапуск приложения |
| Тактильный отклик | Telegram HapticFeedback |
| Системная «назад» | Свой стек оверлеев + BackButton Telegram |
| Безопасные отступы | Из Telegram в CSS-переменные, обновляются на лету |
| Календарь | `.ics` генерируется на клиенте |
| Картинки сторис | Canvas 2D, скачивание из браузера |
| Карта | Статический embed OpenStreetMap |
| Геокодирование адреса | Сделано один раз при разработке, координаты зашиты |

## 6. Безопасность

- **`#studio` в адресе открывал кабинет мимо PIN** — база клиентов, телефоны, инстаграмы и выручка были доступны любому, кто знал хеш. Закрыто в двух местах: экран убран из восстанавливаемых из URL, плюс проверка сессии внутри. Покрыто тестом.
- PIN-коды и роли **лежат на клиенте** — это прототип. На бою вход обязан быть проверкой Telegram-ID на сервере.
- Анкета здоровья и результаты разборов хранятся на устройстве клиентки. В кабинете мастера сейчас видны только «свои» — это ограничение прототипа, а не задумка.

## 8. Чего не хватает на бэкенде

По убыванию важности.

### 8.1 База данных и синхронизация — без этого продукт не выходит из прототипа

Всё из §7 должно переехать на сервер с привязкой к Telegram-ID. Это снимает разом три ограничения: история на любом устройстве, Анжелика видит анкеты клиенток, записи не теряются.

**Нужно:** БД (записи, клиенты, анкеты, результаты, покупки, задания, команда, прайс), REST или tRPC, авторизация проверкой подписи `initData` на сервере.

### 8.2 Оплата Stars по-настоящему

Сейчас `payWithStars` вне Telegram симулирует успех, а внутри Telegram идёт за ссылкой на `/api/invoice`, которого нет.

**Нужно:** эндпоинт, вызывающий Bot API `createInvoiceLink` (валюта XTR), обработчик `pre_checkout_query`, вебхук `successful_payment`, запись покупки в БД. Токен бота на сервере — на клиенте его быть не должно.

### 8.3 Уведомления

Настройки уже есть и сохраняются, но ничего не отправляют. Перечень из голосовых Анжелики: клиентке за 24 часа и утром в день процедуры, уход после, запрос отзыва через 2 недели, бонус за отзыв с фото через месяц, напоминание о повторе через 1–3 месяца; Анжелике — за 30 минут до следующего человека.

**Нужно:** очередь отложенных задач, `sendMessage` через Bot API, отслеживание права на рассылку.

### 8.4 Реферальная программа

Ссылка с меткой генерируется, но переход никто не считает.

**Нужно:** разбор `start_param` при входе, фиксация «пришла от такой-то», начисление 10% скидки пригласившей.

### 8.5 Живой AI

`lib/ai.ts` — 19 правил сопоставления. Отвечает бодро, но это не диалог.

**Нужно:** прокси к языковой модели с контекстом (каталог, прайс, анкета клиентки, её история), ограничение по темам и явный отказ от медицинских советов.

### 8.6 Медиа

Фотографии работ сейчас — сток (`PHOTO-CREDITS.md`). Пары «до/после» подготовлены в коде (`RESULT_PAIRS`), но пусты: настоящие снимки должна дать Анжелика.

**Нужно:** загрузка фото мастером, хранилище, согласие клиента на публикацию.

### 8.7 Мелочи, требующие сервера

- PDF-отчёт по разбору кожи.
- Экспорт клиентской базы.
- Аналитика по нескольким устройствам.
- Резервные копии.

## 9. Дизайн-система

| | |
|---|---|
| Цвета | Петроль `#0A1A1F` (холст), изумруд `#12C088`, золото `#F5C842` |
| Поверхности | Три ступени сплошным цветом: `#0E2126` → `#12272C` → `#183038` |
| Текст | Четыре уровня: 0.97 / 0.74 / 0.54 / 0.38 |
| Шрифт | Inter, табличные цифры в ценах и счётчиках |
| Кегли | Лестница 10·11·12·13·14·15 / 16·17·18·20·22·24·26·28 |
| Кнопки | Три ступени: золото (первостепенная) · залитая (второстепенная) · стекло (Закрыть, Отмена) |
| Движение | `--ease-out: cubic-bezier(.16,1,.3,1)`, `--ease-spring: cubic-bezier(.34,1.56,.64,1)` |
| Мишени | Не меньше 44px — у мелких контролов зона расширена невидимым `::after` |

**Дисциплина зелёного:** цвет бренда означает состояние, цену и активную вкладку. Надзаголовки, подписи и иконки — нейтральные. Иначе глаз перестаёт отличать «тут можно нажать» от «тут просто написано».

**Честность данных:** иллюстрация процедуры и доказательство результата — разные поля данных (`servicePhoto` и `serviceResultPair`). Шторка «до/после» показывается только при настоящей паре снимков.

## 10. Тесты

33 теста Playwright на WebKit / iPhone 13 — движок iOS-телеграма, а не Chromium.

| Файл | Что проверяет |
|---|---|
| `states.spec.ts` | Пустой аккаунт на всех экранах, незаполненный паспорт даёт действие, модальный закон (три способа закрытия), 320px, мишени ≥40px |
| `flows.spec.ts` | Галерея → карточка → запись, paywall → чек → разбор, квиз до результата, скидка не даётся тапом, язык переживает перезагрузку, несколько процедур в визите |
| `studio.spec.ts` | Доступ по ролям, кабинет не открыть по адресу, сверка противопоказаний, отсутствие ложных тревог, архив не ломает историю, проверка заданий, промо-студия |
